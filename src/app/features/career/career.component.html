How are the points calculated?

Rubric v{{ scoringVersion }} assigns 100 possible points per repository: README 20, commit messages 15, code-maintenance practices 20, documentation 20, and automation/stewardship 25. Checks have explicit weights; ratios earn partial credit. The overall score is 100 × earned ÷ assessed weight, pooled across the selected repositories. Missing evidence can change effective category weights; category bars are independent percentages, not additive points.

We withhold scores below 60% weighted coverage. Unknown evidence is not a failure. The range shows the result if all unknown checks failed versus all passed; it is not a statistical confidence interval. Custom weights and thresholds are transparent product choices, not validated predictors of performance or hiring success.

We inspect up to six recently pushed, non-fork, non-archived repositories from the latest 100, excluding your profile README repository. This is a selected portfolio sample, not your entire GitHub activity.

Per repository: root README, up to two documentation files, three source files spread deterministically across sorted paths, up to 30 user-attributed default-branch commits, and up to 10 GitHub Actions runs. Files over 100 KB remain unknown. API reads occur over an analysis window, not an atomic snapshot. Private work, forks and contributions to other owners are outside this report.

English and Arabic section keywords are recognized; other languages and documentation conventions may be missed. Commit counts, dates, stars and followers earn no points. At least three non-merge commits are needed to assess message patterns. Configuration presence does not prove checks pass; successful workflows do not prove tests ran. Four low-weight source-style points do not measure clean architecture or correctness.

Informed by OpenSSF Scorecard, OpenSSF Best Practices and SPACE research. This is an independent rubric, not an OpenSSF score, certification or developer ranking.
